# wb-ozon-ip-evidence

Сбор пакета доказательств копирования контента для жалобы на WB/Ozon.
Для каждой чужой карточки (артикул WB или URL):

- название, бренд, ID продавца, дата создания карточки (WB, публичный basket API)
- все изображения карточки → `evidence/<platform>_<sku>/`
- скриншот страницы (через Chrome с `--remote-debugging-port=9222`)
- итоговая таблица `evidence/evidence_report.xlsx` — «нарушитель → материалы»

В комплекте `claim_template.md` — чек-лист и шаблон пакета доказательств
для жалобы маркетплейсу.

## Запуск

```bash
pip install -r requirements.txt
python collect_evidence.py refs.txt            # полный сбор (WB + скриншоты)
python collect_evidence.py refs.txt --no-shot  # без скриншотов, быстрее
```

`refs.txt` — по одному артикулу WB или URL карточки (WB/Ozon) на строку.
Пример — `refs_test.txt`.

## Вывод (реальный прогон)

```
WB 34036071
saved: evidence/evidence_report.xlsx
```

В отчёте по карточке 34036071: название, бренд «Leon medikal»,
seller_id 194495, дата создания 2021-07-06, 25 фото выгружены.
Демо-отчёт — `docs/demo_evidence_report.xlsx`.

## Ограничения (честно)

- Публичные эндпоинты WB отдают `seller_id` и бренд, но **не торговое
  имя продавца** — его смотрите на странице карточки/в скриншоте.
- `basket-*.wbbasket.ru` местами нестабилен — в коде ретраи (5×25с),
  но отдельные прогоны могут закончиться с пометкой об ошибке в
  колонке «Примечания». Просто перезапустите.
- Ozon отдаёт только скриншот страницы (API требует seller-ключи) —
  остальные данные фиксируются со скриншота.
- Скриншот требует открытый Chrome с CDP-портом 9222; без него —
  `--no-shot`.
